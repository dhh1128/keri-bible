## 1. What an ACDC credential fundamentally IS (as embodied by these schemas)

### The ACDC envelope is fixed and sacred
House style: "Never restyle the ACDC envelope." and "Their terseness earns its keep (universal, and in the compact form they are all that ships)." (`docs/style.md` §Rules 5, :24-26, `cfcbdcc7a`). Domain fields (members of `a`/`e`/`r` beyond the envelope) use camelCase and "appear only in the *expanded* form, so their verbosity costs nothing on the wire" (same, :26-27).

**Superseded in part, 2026-10-03.** The note's field list ~~`v / d / u / i / ri / s / a / e / r`~~ is the **ACDC v1** envelope, and `docs/style.md`:24 still lists it. The schemas themselves have moved on: GCD 3.0 credentials "are `acm`/JSON messages whose top-level fields appear in the order `[v, t, d, u, i, rd, s, a, e, r]`" (`gcd/index.md` §Schema, :34-35), and "`rd` (the SAID of the issuer's credential-status registry inception) replaces v1's `ri`" (:36-37). The whole SEDI family followed (`this.i` `@lkfnoess`, :2132-2133: "sedi-id, sedi-guardian and sedi-present-age-portrait all move to the v2 envelope ('ri' -> 'rd', 't' pinned to acm)"). The style doc is stale on this point; the house rule (don't restyle the envelope) stands.

### `$id` is a SAID — content-addressed, self-certifying schemas
"**`$id` is a SAID.** It is derived from the saidified schema content." … "Never invent or hand-patch a SAID." (`KNOWLEDGE_TRANSFER.md` §Hard facts 1, :88-90). `registry.json` is "the crawl-free index of released schemas (`SAID → path`)" (same, :91-92), so schemas "are discoverable without crawling" (`README.md` §What's here, :20). "keri is the SAID oracle, pinned exactly" (`README.md` §Tooling, :72-73). The oracle is now the `bakobo/keripy` fork, not a released keri: `this.i` `@sd2qfw` (:1907-1909) records that `@h3or4x` "moved the oracle to bakobo/keripy@a1f2f32b (keri 2.1.0-dev0), which stamps v2".

A rules block is a content address too, and the corpus now keeps every published revision: "A rules SAID in an issued credential is a permanent content address." (`this.i` `@jmr6znql`, :2267-2268).

### The compact/expanded `oneOf` pattern (graduated disclosure at the structural level)
"Each block (`a`, `e`, `r`) is either a SAID string (compact) or the full object (expanded). Preserve both arms." (`KNOWLEDGE_TRANSFER.md` §Hard facts 3, :93-94). A withheld field travels as its bare SAID; a revealed one as the full object. "The verifier hashes each disclosed block, substitutes the withheld SAIDs, and recomputes `a.d` to confirm the disclosure is authentic." (`sedi-id/index.md` §Selective (partial) disclosure, :117-118). In v2, the order of the arms is load-bearing: "the compact SAID-string arm stays FIRST in every oneOf, which the most-compact-form SAID algorithm keys on" (`this.i` `@enr3eg`, :299-300).

New since the first pass: the arms were missing where it mattered most. Sam's Core at `ec307cd74` "accepts only expanded objects for its named attribute blocks and utahAgent edge", so "an issued Core or its selectively disclosed form fails schema validation" (`this.i` `@spytom65`, :2302-2305). Bakobo amended it; Sam's own later Core carries the arms (`@3x2jtfxc`, :2322), but some edges still lack one: "The `utahAgent` edge has no compact arm, so an issuer or holder compacts the whole edge section or keeps the edge expanded." (`sedi-core/index.md`, :3). A related tooling defect was found and fixed: schematools "computed each nested block's SAID over the block with its own child blocks still expanded", where keripy computes it over the most compact form (`this.i` `@5lffczug`, :2326). The general lesson the corpus draws: "compare against the builder the protocol actually uses, not against a primitive that merely looks like it should agree." (`this.i` `@lkfnoess`, :2164-2165).

### Two graduated-disclosure mechanisms: attribute (`a`) vs aggregate (`A`)
The single most reusable design doc in the corpus. Both blind each withheld field "by a per-block nonce so its value can't be brute-forced from its SAID" (`docs/choosing-attribute-vs-aggregate.md` §The two graduated-disclosure mechanisms, :13-14). They differ in top-level block shape:
- **Attribute section (`a`)** — "a **labeled field map**" (:17). "Field labels are public (they're in the schema)." (:19) → partial disclosure.
- **Aggregate section (`A`)** — "an **ordered array of unlabeled blinded blocks**, committed by a zeroth-element AGID" (:20-21). "The block labels live *inside* each block, so they're blinded; array position is arbitrary." (:22) → selective disclosure.

The deciding question: "**Does hiding the field *labels* or *positions* buy you anything?**" (§The deciding question, :26). The aggregate is valuable in exactly two cases (:32-36): "The **presence or identity of a field is itself sensitive**" and "The **field set is variable or homogeneous**". Otherwise "the aggregate is **pure cost**, because you lose **label-based pathing**" (:38); negotiation "wants to name a field as `a/residenceState`. In an aggregate you can't" (:40). Rule of thumb (§The rule of thumb, :46-50): a fixed heterogeneous labeled set → `a`; a homogeneous vector disclosed in subset → `A` ("matches mDL, upgrades to a sparse Merkle tree", :49); a set whose shape is secret → `A`.

Caveat worth quoting: "**Attribute-form partial disclosure forces the issuee (`a.i`) and the `a`-section metadata to be revealed** on any disclosure; an aggregate can disclose one element with no issuee." (§Caveats worth remembering, :65-66).

The worked case changed underneath this doc. Its SEDI example now reads "age-threshold flags `over13` through `over70` (Sam Smith's schema at keripy `9a8b7aa7`)" and "Sam reached the same choice independently" (:58). Its last caveat (:68-71) still describes the keri 1.2.13 oracle limitation that `this.i` `@sd2qfw` records as "LIFTED by @lkfnoess (2026-09-15)" (:1907) — the doc is stale on that point.

**A security weakness in the aggregate shape, recorded and deliberately not yet fixed.** Sam's Age schema "does not pin `coreIdentity`'s far schema or the blocks' array positions" (`sedi-age/index.md`, :5). `this.i` `@lkfnoess` (:2144-2147) spells out the consequence: "the AGID is not pinned at index 0 and the issuee block is not required at index 1, which lets a holder withhold element 1 and present a targeted credential as an untargeted affidavit." Bakobo sequenced the fix upstream-first ("fix the example in bakobo/keripy, raise a PR there, then contribute it back to WebOfTrust/keripy", :2150-2151; tick `6grq`). JUDGMENT for Daniel below.

**Confirmed against keripy, second pass.** The shape is unchanged at `80f77b73b` (§4, "What Sam's fixtures show"), and keripy's library depends on the position the schema leaves free: the issuee of an aggregate ACDC is read "for aggregative ACDC .sad["A"][1]['i']" (`src/keri/core/serdering.py`:2830), by `agg[1].get("i")` inside a bare `except` that returns `None` (:2837-2844). An Age whose element 1 is withheld, or whose issuee block sits anywhere but index 1, therefore reads to keripy as untargeted. `[K]`. What saves the IPEX path at this pin is a different rule — keripy's IPEX grant verification rejects a registry-backed ACDC with any withheld `A` element at all (§9 item 8; narrowed 2026-10-03 by verification from "refuses to grant": the check runs when a grant is verified, not when one is built) — which closes the targeted-as-untargeted hole by also closing selective disclosure.

## 2. Edges, chaining, and the operators (I2I / NI2I / E1E)

### Edges are typed pointers with operators that bind identity
An edge names a far node by SAID (`n`), pins the required schema SAID of that node (`s`, often `const`), and carries an operator `o`. Three operators now appear on `main`:
- **`I2I`** — the issuer of this ACDC is the issuee of the far node. GCD: "Operator indicating issuer AID of this ACDC MUST be the Issuee AID of the node this Edge points to." (`gcd/gcd.schema.json` `e.issuer.o`, :369).
- **`NI2I`** — the far node need not be issued to this issuer. ~~Used when a guardian points at a ward's credential the guardian did not receive.~~ **Superseded, 2026-10-03:** that was `sedi-guardian` 2.0.0's `subject` edge, now archived; the guardian "named the ward by an outgoing `subject` edge" (`sedi-guardian-2.0.0/index.md`, :3). At `cfcbdcc7a`, `NI2I` appears on Sam's Age edge to Core (`sedi-age/example.json` `e.coreIdentity.o`, :90-93: `["E1E", "NI2I"]`), on the members of Core's `guardians` group, which a verifier must hold "to the guardianship schema and `NI2I`" (`sedi-core/index.md`, :3), and as an allowed value on `sedi-guardian`'s `authorization` and `constraints` edges (`sedi-guardian/sedi-guardian.schema.json`, :358-361, :402-405).
- **`E1E`** (new) — an identity relation on the issuees. `sedi-guardian`'s `citizen` edge: "Same-issuee identity relation" (`sedi-guardian/sedi-guardian.schema.json` `e.citizen.o`, :316). `this.i` gives the semantics and its source: "E1E is an IDENTITY relation — near issuee = far issuee, issuer unconstrained (keripy discussion #1515)" (`@lkfnoess`, :2123-2124). Sam's Age schema types `o` as an array of strings (`sedi-age/sedi-age.schema.json`, :592-598), so operators compose: `E1E` and `NI2I` together.

**What keripy does with these operators, `[K]` at `80f77b73b`.** keripy recognizes five unary operators, `UnaryEdgeOps = ("I2I", "NI2I", "DI2I", "E1E", "NOT")` (`src/keri/acdc/ipexing.py`:44; the verifier's `UnaryOps` at `src/keri/vdr/verifying.py`:43 is the same set). Two of them are listed only to fail loudly: "DI2I and NOT are recognized but unimplemented" (`verifying.py`:38). E1E is implemented as the issuee identity the bakobo record describes: the near ACDC's issuee "MUST equal the issuee AID of the far node" (`verifying.py`:459, under the heading comment "Identity relation (discussion #1515)", :458), and the comment names the SEDI case — third-party issuer, same subject — as "valid (and is exactly what I2I rejects)" (:462). The composition rule for a list-valued `o` is that the delegative operators (I2I, NI2I, DI2I) conflict and the latest wins, while E1E constrains "the near issuee instead, so it does not conflict with them and composes" (:431). So `["E1E", "NI2I"]` means "same issuee, issuer unconstrained", which is what the SEDI leaves need. keripy's comment also states E1E's normative status: "E1E is normative on the spec's v1.1 branch (kswg-acdc-specification#197)" and "absent from the 1.0 text currently under ToIP ratification" (`verifying.py`:40-41). That is keripy's statement about the spec, not a spec read; this note did not open the spec, so E1E stays at most `[N1.1]` on keripy's word (§9 item 5). Fixture evidence that the distinction bites: `test_residence_sedi_rejects_invalid_issuee_relationship` builds a Residence whose edge to Core declares `["I2I"]` and asserts the grant fails, with the docstring "Reject authentic SEDI nodes whose declared I2I relationship is false." (`tests/sedi/test_ipex_sedi.py`:2803, :2836).

**public-schema names the same operator set, minus E1E.** At `95a07e544` every edge of `vvp-dossier` describes four operators, including "DI2I: issuer AID MUST be the issuee AID or a delegated AID of the issuee AID of that node." and "NOT: inverts the validity of the node this edge points to." (`vvp-dossier/vvp-dossier.schema.json`:122), as an `enum` of `I2I`, `NI2I`, `DI2I`, `NOT`. The same description opens "I2I (default)" while the `vetting` edge sets `"default": "NI2I"` (:122, :124) — a local inconsistency, not doctrine.

**The doctrine that survives, restated.** The old lesson ("don't force an edge whose operator semantics you can't satisfy; bind at presentation instead") was half right. Reader's takeaway: choose the operator that states the relation you mean (issuer-to-issuee, issuee-to-issuee, or none), rather than dropping the edge.

This is the opposite direction from the vLEI ladder and from bakobo's SEDI presentations, which pin `"const"` far-schema SAIDs (§4). Read together with keripy's verifier, it is not a weakening of the graph: keripy's verifier comment says the edge `s` "is a schema the far node must" (`src/keri/vdr/verifying.py`:196) "*satisfy*, not a SAID that must equal the far node's own schema" (:197) SAID, citing issue #1534, and the code validates the far node against a differing edge schema rather than rejecting it (:208-228), so a verifier still checks the far node against whatever `s` the issued edge carries. What the schema no longer does is restrict which `s` an issuer may write. That restriction moves to the verifier's policy, the same "schema checks shape, verifier decides" split §8 records for GCD. Interpretive; neither repo states the reason.

### Edges ≠ constraints (a load-bearing distinction in GCD)
`proofs` "identifies schemas for proof requests in the IPEX protocol" … "*This constraint should not be confused with ACDC edges (chained credentials), which justify the delegator's status in the first place, and which are the SAIDs of concrete credentials rather than identifiers of schemas which could satisfy a constraint.*" (`gcd/index.md` §Constraints, `proofs` bullet, :69). ## 3. GCD — Generalized Cooperative Delegation (the crown jewel)

GCD is at version 3.1.0 on `main` (`gcd/gcd.schema.json` `version`, :9; `$id` `EDqAod5ZiCNfQziVHjOALNNRabw2iwpAYqqOsEXUcxm5`, :2). ### What GCD is and is NOT
**Superseded, 2026-10-03.** The first pass quoted ~~"The delegation relationship itself is **not embodied in a credential**, but rather in a special delegate AID bound to the delegator's AID via an inception event on the delegate side, and an interaction event in the KEL on the delegator side …"~~ That wording is still at public-schema `gcd/index.md`:7 (`8db57eb`, and unchanged at `95a07e544`), but bakobo removed it in GCD 2.0.1. (The struck first-pass quote was not verbatim: the source reads "not embodied in a credential, but rather in a special delegate AID that's bound to the delegator's AID", without bold.) The current Purpose:

"These credentials document the authorizations, constraints, and duties of **delegated authority**" (`gcd/index.md` §Purpose, :5). KERI cooperative delegation remains "The paradigmatic and strongest way to bind a delegate to a delegator" (capital restored 2026-10-03; the first re-anchor had lower-cased it) and "the exemplar these credentials were named for" (:7), "**But it is not a precondition.**" (:9). "A GCD credential is a standard targeted ACDC; its authorization and constraint mechanics do not depend on the issuee being KEL-anchored to the issuer." (:9). What survives intact: "Whichever binding is used, it only proves the *state* of the delegation relationship and defines how it is controlled." (:11) — GCD's job is the actions and constraints the binding does not specify.

The decision record names the precision that keeps this from weakening GCD: "what is decoupled is "delegated AUTHORITY" (which GCD documents, no KEL anchoring required) from "KERI COOPERATIVE-DELEGATION KEL binding" (a stronger, optional fact)." (`this.i` `@n8wq3d`, :258-260); dip+ixn "is now the EXEMPLAR, not the gate" (:263). The external driver was PAP, whose signer "is an INDEPENDENT role AID … NOT a cooperative-delegate of the authorizer" (:268-269). The schema's issuee description now says so too: "GCD does not require a KERI cooperative-delegation binding" (`gcd/gcd.schema.json` `a.i`, :70).

### Authority is always proved by a signature
"In the digital world, authority may be asserted in many ways, but it is always proved by a digital signature." … "the question GCD credentials answer is whether the delegate had the authority to act in behalf of the delegator when they affixed that signature." (`gcd/index.md` §Types of authority, :20). Contrast the physical world, where the treasurer's vault key and the treaty "have different affordances" (:18). Unchanged.

### `rd` is required — the one place GCD overrides a spec default (new)
`rd` is required: "the ACDC spec makes `rd` optional for correlation minimization, but a GCD is authority evidence, so secure discovery of its revocation registry wins here." (`gcd/index.md` §Schema, :37-40; schema `rd` description, :41). The decision adds that correlation-minimized delegation is not a GCD use case, and "a schema that let rd be omitted would fail open on the discovery a verifier gates on." (`this.i` `@enr3eg`, :308-309). The issuer edge stays optional because heti "refuses edge-bearing ACDCs by name until a real consumer needs chains" — "edges remain the exemplar chaining mechanism, not the gate" (:316-318).

### The v2.0 shape: named containers, not flat prefixes
Still the shape at 3.1.0: version 2.0 "organized the attributes block into named containers (facet, constraints) with sibling voiding (terminatingEvents) and outbound-disclosure (disclosables) axes" and first-classed duties in the rules block (`gcd/gcd.schema.json` `description`, :5). `r` holds five disclaimers plus `duties`.

**`facet`** (descriptive, forward-compatible): "Unknown keys here are safe to ignore (forward-compatible), so this container is NOT fail-closed." (schema `a.facet`, :86).
- `role` — "When gfw is NOT defined, this field becomes a simple descriptive label, and no party is justified in expecting it to convey any constraints." (:90); rule `noRoleSemanticsWithoutGfw`.
- `relationType` — "delegation: the delegate acts for a self-sovereign delegator. guardianship: the delegate acts for a non-sovereign dependent. controllership: the delegate acts over a thing." (:99), plus "stewardship: guardianship's fiduciary posture applied to a domain the steward runs as their own." (:99).
- `liableParty` — "Who answers OUTWARD if an act taken under this delegation goes wrong -- the party the world holds responsible." (:109). Renamed from the paper's `obligationBearer` (`KNOWLEDGE_TRANSFER.md`, :49-50).
- `presentsAs` — "Presenting-as without this granted capability is impersonation. The signer is always the actor's own key; presentsAs governs only the presented identity, not the signature." (:113).
- `exerciseMode` — `act` / `authorize` / `both`; `authorize` is "the pure delegator, with an empty set of goals, who may sanction others' gated acts but performs none itself" (:117). "authority-to-act vs authority-to-authorize as independent axes" (`KNOWLEDGE_TRANSFER.md`, :52-53).

**`constraints`** — the enabling "may".

**Superseded, 2026-10-03:** ~~FAIL-CLOSED (`additionalProperties: false`): an unrecognized key here MUST deny.~~ As of 3.1.0 the container is `"additionalProperties": true` (schema :130). The rule that an unknown key denies is unchanged, but it moved from the schema to the verifier: "This container remains FAIL-CLOSED, but the obligation runs to the verifier, not to schema validation" (schema `a.constraints`, :128). `gcd/index.md` (§Custom constraints, :102) states the consequence as doctrine: "Validating against this schema is not an authorization decision". `this.i` `@vy7qoj` (:342-348) gives the driver — `gfw` and `useStdIfPossible` both presupposed custom constraints that `additionalProperties: false` made "dead letters" — and the intent: "a verifier MUST fail closed … but the credential as an embodied artifact does not have to enforce this" (:349-351). Accepted tradeoff: "a verifier that gates on schema validation ALONE loses a free backstop" (:360-361). Rejected: namespaced `x-` keys and requiring `gfw` whenever a custom key appears (:364-371). Note that `KNOWLEDGE_TRANSFER.md`:54-55 still says "**fail-closed** (`additionalProperties: false`)" — stale.

Fields (each optional; absent = that dimension unconstrained):
- `goals` — Aries goal codes, "matched as if they contained a trailing .* wildcard", "case-insensitive" (:133).
- `acts` — "The set of (effect, state-kind) POINTS this delegate may act on" (:149). effect ∈ {observe, create, modify, preserve, destroy}; state-kind ∈ {info, record, commitment, authority, resource, relationship} — "the two axes of one coordinate, neither meaningful alone" (:149). "An act is authorized only if EVERY (effect, state-kind) point it occupies is covered here." (:149). "Two-sided braces and wildcards are intentionally not allowed." (:149). The gate "is DERIVED per act from its points and its target via the governance framework (gfw), not enumerated here" (:149). Filing a return "is `create record` *and* `create commitment` in one move" (`gcd/index.md`, :61).
- `domains`, `jurisdictions`, `physGeos` ("MUST be determined by a strong test of physical presence", :195), `virtGeos` ("may be weaker than physGeos", :212), `icals` (RFC 5545), `monetaryLimit`, `protos`, `proofs` ("the array is an OR", :266), `validFrom`/`validUntil`, `humanReview`.
- `monetaryLimit` — "This field is money-locked: it is NOT a general 'stakes' quantity. Non-money or unquantifiable stakes route to the governance gate, not here." (:242). Pattern `^[0-9]+(\.[0-9]+)? +\S+$` (:244); examples "25 CHF", "0.3 BTC", "4 OZ-XAU".
- `humanReview` — "Any GCD credential that has this field MUST NOT be verified without human judgment." (:288).
- Custom keys (new at 3.1.0): "A custom key takes its semantics from the governance framework named in `gfw`" (`gcd/index.md` §Custom constraints, :93-94).

**Boolean logic of constraints (invariant):** within a field values are ORed, across fields ANDed (`gcd/index.md` §Constraints rules 2–3, :83-84). Consequence, unchanged: "Because of the third rule, these credentials do not support graduated disclosure. All constraints must be disclosed every time a verifier is evaluating delegated authority." (:86).

**`terminatingEvents`**: "ANY one firing ends the authority" … "These are proof-shaped attested facts, not live predicates, so the credential's meaning stays static and any two verifiers replay to the same result." (schema :294). The `validUntil` backstop is enforced by an `if`/`then` (schema :318-334; was :316-332), "so a never-fired termination signal cannot leave authority alive forever" (`validUntil`, :283).

**`disclosables`**: "an allow-list at schema granularity. Intra-credential selective disclosure remains ACDC's job." (schema :306).

### The five disclaimers (rules block, all required) — quotable doctrine
From `gcd/rules.json` (`d` `ENiUyBCG2MjCHa9djlgHiogd6uZHECc09ZELmQ3fEMzR`, :2), byte-identical across 3.1.0 per `@vy7qoj` (:359-360):

3. `noConstraintOutsideConstraints` — "enforceable constraints exist only inside the constraints container, or in the role field when gfw is defined." … "an unrecognized key inside the constraints container MUST be treated as fail-closed." 4. `useStdIfPossible` — "This allows verifiers to be confident that when one of the pre-defined constraints is absent, delegated authority is unconstrained in its corresponding dimension." (:6). (The first pass paraphrased this as "so verifiers can be confident"; corrected to the source wording.)
5. `onlyDelegateHeldAuthority` — "Issuers agree to only delegate authority that they reasonably believe they hold." (:7).

### Duties (the "must", first-class in `r`)
"Duties are disclosure and accountability -- a stranger-verifier does not gate on them -- so they live here in r, not in a.constraints." (schema `r.duties`, :526). Discussion [#1098](https://github.com/WebOfTrust/keripy/discussions/1098) proposes a static sparse-Merkle-tree predicate proof, not a vector of booleans:
- The problem: "a static a priori issuance of a given proof of age could become invalid as the individual's age changes." `[P]`
- Why not ZKP: "ZKPs are not a viable solution to the proof-of-age problem with KERI/ACDC-based proof-of-age entitlements." `[P]` — because unlinkability defeats detectability of issuer (and holder) key compromise; the holder half is `raw/16`'s.
- The construction: "The issued ACDC includes an attribute that is the Root of the SMT." `[P]` One leaf per date on which a predicate is true, with daily resolution up to a maximum age of 100; "A proof-of-age is given by an inclusion proof of a given predicate leaf in the SMT." `[P]`
- Blinding: each leaf is salted from a secret shared at issuance, so "only 2nd parties to a disclosure can construct a valid query of the SMT." `[P]`
- The verdict: "a static SMT predicate proof preserves KERI's security properties, whereas a dynamic ZKP predicate proof defeats them." `[P]`
- Candid limits: "age-range predicate proofs provide only weak protection when used in isolation." `[P]` (social engineering — a child logging in on their thirteenth birthday reveals it). And the reframing: "In this light, birthdate privacy is relieving the symptom, not curing the disease." `[P]` — the disease being birthdates used as shared-secret authenticators, which KERI does not use.
- The Utah threshold list Sam gives: ">=13 for social media, >=14 for employment, >=15.5 for learner's permit, >=16 for driving, >=18 for voting, and >=21 for drinking." `[P]`

Comparison (interpretive, flagged as such). Citations are "designed to be referenced *only* via the edge of another ACDC" (:33).

- **Treating schema validity as authorization** (new) — "Validating against this schema is not an authorization decision" (`gcd/index.md` §Custom constraints, :102).
- **Confusing constraint-schemas (`proofs`) with edges** (`gcd/index.md`, :69).
- **Assuming a signature proves affordance-limited authority** (`gcd/index.md` §Types of authority, :18-20).
- **Role labels as if self-describing** — `noRoleSemanticsWithoutGfw` (`gcd/rules.json`, :3).
- **presentsAs without the granted capability = impersonation** (`gcd/gcd.schema.json`, :113).
- ~~**Forcing an edge whose operator can't be satisfied** — sedi-age deliberately omits the edge.~~ **Refined 2026-10-03:** the tell is choosing the wrong operator, not having an edge; Age now carries an `E1E` edge (§2).
- **A discriminator flag on a security boundary** (new) — "make them DISTINCT schemas, never one schema with a discriminator flag" (`this.i` `@sdlg3n`, :2083).
- **An edge where none is needed** (new) — the ballot receipt omits an edge to the presented credential because it "would join the receipt to that copy for every later verifier" (`sedi-ballot-receipt/index.md`, :25).

### Foreign-artifact bridging (FAA) — the "not-a-CA" interop stance
FAA "gives non-ACDC data the attributes that are needed to participate fully in an ACDC data graph" (`faa/index.md` §Purpose, :5) and "places non-ACDC data in an efficient, tamper-evident envelope with predictable metadata" (:11). ## 6. Levels of assurance (org-vet) — LoA as verifier-chosen threshold, not CA hierarchy

`org-vet/index.md` (bakobo `cfcbdcc7a`, now version 2.0.0): LoA is "a positive number, where larger numbers map to higher levels of assurance" and "This allows verifiers to decide what level of assurance will satisfy them, and accept any credential having an LoA >= their threshhold." (§Levels of assurance, :14). Bronze adds "Prove requester has modified a DNS record for the domain to claim the issue's cryptographic identifier (AID)" (:18); silver requires eIDAS substantial / NIST IAL2, cryptographic proof of authorization via a GCD credential and/or a KERI delegated AID, and "at least 1 witness" (:19); gold requires a ceremony proving "there is no MITM between any two members of the signing committee", and between each member and at least one external observer, plus "enough witnesses to reliably detect and recover from duplicity" (:20). Duplicity detection-and-recovery, MITM-freeness, and external observers are the LoA-3 primitives. ~~"The LE vLEI is essentially an org-vet credential at LoA 3."~~ → verbatim, the LE vLEI "is essentially an org vet credential at LoA 3, but its schema varies slightly to express some GLEIF governance requirements." (§Purpose, :5).

**public-schema went another way (`95a07e544`).** Provenant deleted `org-vet/` and renamed `ovc-org-vet/` to `org-identity/` (commit `c0bc062`). The LoA table carries over nearly word for word — LoA is still "a positive number, where larger numbers map to higher levels of assurance" (`org-identity/index.md` §Levels of assurance, :18) — but the credential is reframed as an identifier binding: it "**connects different identifiers for the same organization**, binding legal entity identity to a cryptographic identifier (AID)" (§Purpose, :5), and is "the foundational trust anchor for the OVC ecosystem" (:7). The LE vLEI comparison becomes "analogous in intent" and "(which maps to LoA 3), but its schema is designed to be simpler and to accommodate a wider range of national registry sources" (:9). Its rules are citation-style (`onlyCommitToPoint`, `useViaEdges`, `undefinedVerification`, `undefinedRevocation`, `governance`; §Rules and governance, :76-80), not bakobo org-vet 2.0's Ricardian clauses. New: "CESR has no RSA code" (:12), so `pubkey` is a plain string with a required `keyFormat`.

### proof-of-control — "parties are only identifiers; there is no 'man' to impersonate"
"As far as the semantics of these credentials are concerned, issuer and issuee are simply identifiers that resolve to cryptographic keys." Many common man-in-the-middle attacks are therefore out of scope, assuming robust identifier-to-key resolution: "there is no "man" to impersonate." (`proof-of-control/index.md` §Parties are only identifiers, :14). Combining with an identity credential "introduces man-in-the-middle issues. These must be handled by the identity credentials." (:16). Assumption-relative: "Issuers should make reasonable efforts to ensure that certain assumptions hold" and "Verifiers should judge their confidence in the credentials with these assumptions in mind" (§Security Considerations, :44). Challenge/response "Over any secure or insecure channel" (:22, :26). Known limitation: a colluding issuee "is indistinguishable from the real controller in the issuance procedure" and "Proof-of-control credentials don't distinguish between these cases." (:42). The schema is now 2.1.0 on the v2 envelope with an optional `validUntil` (reflog; `this.i` `@2n2vtee3`, `@3j5lwc7w`, not read) *(uncited — flagged by verification 2026-10-03)*.

## 8. Cross-cutting design doctrine (reusable rules of thumb)

- **The schema checks shape; the verifier decides.** ~~Fail-closed where a verifier gates (`constraints.additionalProperties=false`); safe-ignore where it merely describes.~~ **Refined 2026-10-03:** the gating/describing split stands, but enforcement of fail-closed moved to the verifier — "Admitting a key is not vouching for it, and validating against this schema is not an authorization decision." (`gcd/gcd.schema.json` `a.constraints`, :128). The SEDI pages say the same about graph checks: "JSON Schema only checks the presentation's local shape and pinned edge operators and far-schema SAIDs." (`sedi-present-age-portrait/index.md`, :7).
- **Authority credentials are disclosed WHOLE; identity/attribute credentials support graduated disclosure.** Holds for GCD (`gcd/index.md`, :86). **Qualified 2026-10-03** for sedi-guardian: its ward block is now "Ward AID in an individually disclosable block" (`sedi-guardian/sedi-guardian.schema.json`, :101) so the guardian can withhold the ward's identity.
- **Evidence in edges, metadata in attributes** (new, public-schema dossiers): "all evidence MUST be carried in e, never in a" (`dossier-base/dossier-base.schema.json`:5 at `95a07e544`). The same instinct as the GCD `proofs`-vs-edges distinction (§2), stated as a rule for a whole credential class.
- **Authority evidence requires its registry** (new): GCD and sedi-guardian require `rd`; the GCD decision overrides the spec's correlation-minimizing default for that reason (`gcd/index.md`, :37-40).
- **Extract-at-the-second-pattern discipline**: "Extract a shared sedi-legal-authority base at the SECOND concrete instance" (`this.i` `@sdlg3n`, :2068). **Tested 2026-10-03:** the second presentation recipe arrived, and the base was still deferred because "a shared base still adds no enforceable rule beyond each concrete schema's edge and disclosure requirements" (`this.i` `@eqbjfpq3`, :2246-2247). The discipline is "extract when a second instance shows a shared enforceable rule", not merely "at the second instance".
- **Two-layer factoring**: GCD for generic relationship machinery, a thin legal-recognition layer for what law specially recognizes (`this.i` `@sdlg3n`, :2064-2068). Weakened in practice: the GCD edge is now optional and renamed, and an unmerged branch would remove it.
- **Distinct schemas at a security boundary** (new): `this.i` `@sdlg3n`, :2081-2083.
- **Intent-first methodology**: "A decision not in `this.i` is not yet made." (`KNOWLEDGE_TRANSFER.md` §House rules, :126-127).
- **Point-in-time, replayable semantics**: `terminatingEvents` are "proof-shaped attested facts, not live predicates" (`gcd/gcd.schema.json`, :294). org-vet 2.0's `assuranceIsPointInTime` applies the same idea to vetting (`org-vet/index.md`, :30).
- **Pin upstream schemas by bytes, not just SAID** (new): "The byte hashes also catch edits to formatting or key order that a schema SAID, which is computed over canonical JSON, cannot detect." (`tools/py/tests/conformance/test_sedi_pins.py`, :5-6).
- **Archive, never replace, a published schema or rules revision** (new): displaced revisions are kept "byte for byte" under archive paths (`test_sedi_pins.py`, :59), because "replacing their registry entries in place would strand existing credentials even though the new graph validates" (`this.i` `@spytom65`, :2311-2312).
